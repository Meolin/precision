# Ballistics Lab

Локальный MVP 2D-полигона, Step 7: четыре стационарные установки игрока против четырёх установок
противника, RTS-выделение, группы управления и очереди огневых приказов.
Basic Cannon / Mortar / Heavy Penetrator, разрушаемый рельеф Soil/Rock, пробитие, рикошет и взрывы с уроном по площади.
Рельеф ослабляет взрывной урон; техническая панель показывает расчёты. React 19, TypeScript, Vite, PixiJS 8
и `@pixi/react`. Без сервера и внешних игровых ресурсов; после установки зависимостей
приложение не требует подключения к интернету.

## Запуск

Требуется Node.js **22.12+** и npm.

```bash
npm install
npm run dev
```

Откройте адрес, который выведет Vite (обычно `http://127.0.0.1:5173`).
Для воспроизводимой установки с существующим `package-lock.json` используйте `npm ci`.

На старте в поле зрения над рельефом находятся три цветных круга и три квадрата.
Они падают под действием гравитации, сталкиваются с актуальным рельефом и друг с другом;
масса, трение и упругость у образцов различаются; небольшая начальная горизонтальная скорость
помогает увидеть инерцию и скольжение. После остановки объекты засыпают,
а разрушение опоры будит их снова. Удары снарядов передают телам линейный и угловой импульс;
квадраты вращаются с учётом своей ориентации при столкновениях. Демонстрационные тела не являются
управляемыми установками и не имеют здоровья; взрывной снаряд вызывает обычный взрыв при попадании.

Не открывайте `index.html` или `dist/index.html` двойным кликом через `file://`:
браузер намеренно блокирует ES-модули в таком режиме и показывает CORS-ошибку.
Для готовой сборки используйте preview-сервер:

```bash
npm run build
npm run preview
```

## Animation Sandbox

В шапке игрового режима доступна developer-вкладка **Animation Sandbox**. В редакторе верхняя строка
содержит переключатель анимаций, меню **Файл** для импорта и экспорта, меню свойств анимации и
статус документа. Через меню **BALLISTICS / LAB · ANIMATION** можно вернуться в Game. Кнопка ▴
скрывает строку, а **☰ Меню** в панели превью возвращает её; освободившееся место занимает превью.
Редактор собирает production-конфигурацию
анимаций одной сущности из PNG-стадий и показывает их непосредственно в текущей игровой сцене:
используются настоящие камера, terrain, world scale и тот же `BuildingAnimationPlayer`, что доступен
production-коду.

Вкладки **Постройка / Idle / Уничтожение / + Custom** имеют независимые слои, ключи, длительность,
звуковые клипы и маркеры. `Duplicate animation` копирует текущую композицию; кастомные вкладки
можно переименовывать и удалять с Undo. ENTITY задаёт ID общей сущности. `Use construction artwork`
берёт изображения, canvas и world bounds из постройки: Idle получает финальное изображение,
уничтожение — его затухание; звуки, маркеры и длительность текущей вкладки сохраняются. Замена
слоёв отменяется через Undo. Переключение анимации останавливает воспроизведение и возвращает курсор к нулю.

1. Загрузите одну или больше PNG-картинок одним выбором. Их локальные Object URL используются только
   для preview; для каждой стадии задайте стабильный `assetId`, который сможет разрешить production
   asset registry. При совпадении имён после нормализации редактор добавляет числовой суффикс к
   `assetId`, чтобы стадии оставались различимыми.
   Список «Слои» постоянно виден слева; PNG можно перетащить в область «Добавить PNG-стадии».
   Добавление сохраняет существующие стадии, ключи, геометрию и переходы. Новые стадии размещаются
   после последней; при нехватке времени увеличьте длительность. «Заменить набор изображений…» —
   отдельное действие, удаляющее старые PNG-стадии и их ключи; общий Undo восстанавливает замену.
   «Заменить PNG выбранного слоя…» восстанавливает изображение одной стадии без удаления ключей.
   Переименование Asset ID подтверждается Enter/blur и не допускает коллизий.
2. Расставьте стадии, milestones, общий canvas/origin и индивидуальные значения позиции, масштаба,
   наклона и pivot по осям. Ctrl/Cmd-клик выбирает отдельные кадры, Shift-клик — диапазон;
   параметры трансформации применяются ко всей выбранной группе.
   Размер видимой alpha-области задаётся отдельно по ширине и высоте в метрах игрового мира.
3. Раскройте `TRANSITION` и выберите один из **40 эффектов** в группах смешивания, масок,
   растворения, движения и искажений. Есть Cut/Crossfade, Fade through color/Flash, направленные
   wipe, clock/radial, iris circle/box/diamond, blinds/checkerboard/stripes/barn door/scanline,
   noise/pixel/luma/ink/burn dissolve, slide/push/zoom/rotate/flip/stretch/bounce,
   blur/pixelate/glitch/wave/ripple/swirl/RGB split.
   Настройки показываются по выбранному эффекту: 11 направлений, Reverse, угол, центр,
   мягкость маски, сила искажения, плотность, noise и seed. Процедурный рисунок с одинаковым seed
   воспроизводится при перемотке; цвет/easing/blend mode края также сохраняются.
   `Начало / Середина / Конец` и ползунок PREVIEW перемещают курсор внутри выбранного перехода.
   Эффект применяется к входящему переходу выбранной стадии; при групповом выделении параметры
   меняются у всех выбранных входящих переходов. Сброс и редактирование поддерживают Undo/Redo.
4. Используйте линейку времени либо Play/Loop. `Spawn Test Building` включает режим размещения:
   полупрозрачный sprite следует за курсором, а клик фиксирует world X/Y; `Esc` отменяет выбор.
   `Test In Game` переносит тот же конфиг и выбранные координаты в обычный вид полигона;
   воспроизведение продолжается между режимами. `Focus building` возвращает камеру к размещению.
   `Restart Animation` запускает воспроизведение с начала рабочей области, `Remove Test Building`
   скрывает временное здание и останавливает изображение и звук.
5. При PNG-импорте sandbox вычисляет границы ненулевого alpha-канала финальной стадии. Они становятся
   исходными `alphaBounds` и hitbox; hitbox можно смещать, менять размер и независимо масштабировать.
6. В секции `Texture / Strong Downscale` настраиваются Linear/Nearest sampling, mipmaps и anisotropy.
   Для сильно уменьшенных обычных PNG рекомендуются Linear + mipmaps.
7. Панель кадров находится справа от предпросмотра и занимает всю высоту редактора. Блоки
   настроек справа изначально свёрнуты и плавно открываются по нажатию на заголовок. Таймлайн
   расположен под окном предпросмотра и совпадает с ним по ширине. Каждый кадр —
   отдельный раскрываемый слой с полосой времени. Перетаскивание начала полосы меняет milestone;
   щелчок и перетаскивание по линейке перемещают индикатор времени. Длительность в секундах,
   частота кадров и рабочая область воспроизведения настраиваются сверху. При изменении
   длительности ключи и моменты появления картинок сохраняют положение в секундах.
8. Раскройте слой и нажмите секундомер рядом со свойством: первый ключ появится у индикатора
   времени. Изменение анимируемого значения в таймлайне или инспекторе автоматически добавляет
   или обновляет ключ на текущем времени. Параметры X/Y показываются парами с отдельным
   редактированием каждого значения.
   AUTO-KEY изначально выключен: неанимируемые свойства изменяют только базовые значения.
   Включите AUTO-KEY для автоматического создания tracks. Inspector показывает sampled-значение
   текущего кадра, как timeline; оба учитывают FRAME SNAP. Ввод чисел подтверждается Enter/blur,
   Escape отменяет ввод; редактирование приостанавливает playback. FPS задаётся явно,
   FIT показывает всю длительность. Общий Undo/Redo действует и на inspector, и на timeline,
   сохраняется при переключении режима; drag/slider записывается одной операцией.
   Ромбик рядом со значением добавляет/удаляет ключ, стрелки переходят к соседним ключам.
   Доступны позиция, масштаб по осям, вращение, прозрачность, наклон и anchor по осям.
   Ключи можно перетаскивать, выделять группой (Shift, Ctrl/Cmd или прямоугольной рамкой),
   копировать/вставлять/вырезать (Ctrl/Cmd+C/V/X), удалять (Delete) и менять интерполяцию
   (Hold, Linear, Easy Ease, Bézier). `GRAPH` оставляет выбранное свойство с его ключами и кривую,
   позволяет перемещать ключи и редактировать Bézier handles выбранного ключа. При перетаскивании
   сохраняются точка захвата и масштаб графика; ручки остаются доступными при совпадении с ключом.
   Linear и Ease In/Out переходят в Custom Bézier без изменения исходной формы кривой.
   Для Easy Ease сначала нажмите `EDIT BÉZIER`: это явное преобразование в кубическое приближение.
   Между ключами с одинаковым значением ручки двигаются только по времени; координаты Y сохраняются.
   Щелчок без перемещения не меняет кривую; одно перетаскивание отменяется одной операцией Undo.
   Слои можно
   переставлять перетаскиванием строки слоя или кнопками ↑/↓; двойной щелчок по имени слоя
   позволяет его переименовать (после импорта имя совпадает с именем PNG-файла). Блок слоя перемещает его начало
   появления, а его правая граница меняет длительность. Пробел переключает play/pause в sandbox
   и не отдаёт команду выстрела.
   Alt + колесо над таймлайном меняет масштаб
   шкалы вокруг курсора, Shift + колесо прокручивает её по горизонтали. `U` оставляет на экране
   анимированные свойства. При фокусе
   таймлайна работают J/K, Page Up/Down, стрелки, Home/End, F9, Ctrl/Cmd+C/V/X и Ctrl/Cmd+Z/Y.
9. `Export Animation JSON` экспортирует текущую вкладку после валидации. Schema v9 включает `worldSize`,
   `alphaBounds`, `hitbox`, `textureOptimization`, stages, `timeline`, tracks с ключами и
   интерполяцией, порядок слоёв и интервалы видимости, transitions, `vfx`, типизированные `sounds`
   и `markers`, процедурные ресурсы, дочерние фильтры и библиотеку `effectPresets`; schema v2–v8 обновляется при импорте; browser/UI state и Object URL не входят.
   `Export Entity JSON` экспортирует все вкладки в `BuildingAnimationLibrary` (libraryVersion 1).
   `Import JSON` распознаёт отдельную анимацию и полную библиотеку; Undo восстанавливает прежний набор.
   Статус «Структура» означает только корректность схемы. Статус «Ресурсы» отдельно показывает
   готовность текстур, а отсутствующий PNG отмечен в списке слоёв; экспорт не упаковывает PNG/аудио.

Последний черновик автоматически сохраняется локально в IndexedDB вместе с PNG и размещением.
Дождитесь `Draft saved locally` перед закрытием страницы. Ошибки хранения показываются в статусе:
если storage недоступен или переполнен, сохраните JSON вручную и оставьте исходные PNG.
Черновик привязан к origin браузера, не синхронизируется и не заменяет production asset registry.
Onion skin — отдельная полупрозрачная копия предыдущей стадии, не меняющая основную анимацию.

Редактор использует три колонки: слои, предпросмотр, свойства выбранного слоя. Таймлайн
расположен снизу и меняет высоту перетаскиванием разделителя или стрелками после фокуса на нём.
При 1440×900 основные области помещаются в окно; на узком или низком экране используется
вертикальная компоновка с прокруткой. Разделы свойств открываются независимо. Общая геометрия
анимации, hitbox и текстуры отделены от трансформации и эффектов слоя; единицы подписаны.
Milestone редактируется в секундах, а в production-конфиге остаётся normalized progress.

Параметры частиц сгруппированы: эмиссия, источник, движение, внешний вид, кривые жизни
и дополнительные настройки. Размеры источника показываются только для выбранной формы.
Режим «Анимация + звук» показывает обе дорожки с общим масштабом и горизонтальной прокруткой.
Буфер копирования ключей, выбор слоя, раскрытые треки, график, масштаб и прокрутка сохраняются
в рамках текущей сессии при смене режима и вкладки; настройки вида не экспортируются в JSON.

Экспортированный JSON не требует конвертации:

Расширенные параметры переходов появились в schema v7 и сохраняются в v9. Импорт v2–v6 автоматически добавляет defaults;
старый Reveal сохраняет направление слева направо. Маски используют исходную opacity слоя без
дополнительного Crossfade; первые и последние кадры перехода не содержат остаточного свечения.
Fade through color и Flash окрашивают силуэт сущности с сохранением alpha, а не весь игровой экран.

```ts
const config = loadBuildingAnimationConfig(json);
const player = new BuildingAnimationPlayer({ config, resolveTexture });
player.setProgress(building.buildProgress);
```

Переключатель **Анимация / Звук** открывает отдельный звуковой таймлайн с общим курсором и рабочей
областью. WAV/MP3/OGG/M4A/FLAC импортируются кнопкой или drag-and-drop; доступность кодеков зависит
от браузера, лимит файла — 100 MB. Waveform показывает амплитуду всех каналов. Клип перемещается
за тело и обрезается за края с Frame Snap. Доступны имя, начало в композиции, смещение внутри
исходного файла, длина, громкость, Fade in/out, Mute и Solo, Duplicate, Split at cursor и Relink audio.
Аудио длиннее оставшейся композиции при импорте подрезается; исходник сохраняется целиком,
и длину клипа можно расширить после увеличения композиции. Звук за концом композиции не воспроизводится.
Ctrl/Cmd+D создаёт копию, Ctrl/Cmd+Shift+D разрезает клип, Delete удаляет его; стрелки сдвигают
курсор на кадр, Shift — на десять кадров, Home/End переходят к границам рабочей области.
Play/пауза, скорость, зацикливание и переход в GAME синхронны для изображения и звука.

`+ Marker` ставит именованную метку на курсоре; её можно перетащить, переименовать и удалить.
Маркеры общие для двух режимов таймлайна и помогают синхронизировать попадания, переходы и звук.
При изменении длительности ключи, milestones и маркеры сохраняют время в секундах;
уменьшение, которое обрезает ключи, маркеры или начало слоя, ограничивается.
IndexedDB-черновик хранит все вкладки и Blob-файлы PNG/аудио. Экспорт JSON содержит только
стабильные assetId и waveform; сами файлы нужно отдельно положить в asset registry или перепривязать
через Relink после импорта на другом компьютере. `BuildingAnimationPlayer` воспроизводит изображения, частицы и эффекты;
Web Audio воспроизводит звуки в клиентском sandbox, вне Pixi player и simulation.

В **PROCEDURAL MEDIA** доступны Sparks, Smoke, Embers, Aura и Ring. Новый генератор начинается
у курсора времени. Aura создаёт мягкое свечение, Ring — кольцо с анимируемыми радиусом и толщиной.
RTS-пресеты добавляют выстрел, попадание, дым повреждения, контур строительства и щит. Контур
строительства требует выбранного изображения. `Save preset` сохраняет ресурс с фильтрами и ключами
в JSON/черновик; для изображения сохраняется стек, который можно применить к другому ресурсу.
`Copy filters` / `Paste filters` переносят стек, `Duplicate` копирует генератор с зависимостями.

**ATTACH TO SELECTED RESOURCE** предлагает Glow, Blur, Bulge/Pinch, Outline, Ripple, Heat distortion
и Color adjustment. Фильтр появляется вложенным фиолетовым слоем под ресурсом, с именем родителя;
выбор подсвечивает связь. Порядок дочерних слоёв определяет порядок применения. Сила и её диапазон
зависят от типа: Bulge/Pinch допускает −1…1. `Mix` отдельно смешивает исходное и обработанное
изображение. Центры Bulge/Pinch и Ripple поддерживают Composition и Resource local.
Фильтры можно прикрепить к изображению и любому генератору; цепочки фильтр → фильтр запрещены.
Фильтр действует только при видимом родителе. Удаление ресурса удаляет фильтры и их ключи.

Превью показывает EMITTER, ORIGIN и центры радиальных фильтров. Перетаскивайте маркеры, ручки
направления, разброса, радиуса и размеров источника; стрелки сдвигают значение, Shift увеличивает
шаг в 10 раз. `ORIGINS` скрывает маркеры. Манипуляторы учитывают трансформации, camera/world scale
и локальное пространство; AUTO-KEY и существующие tracks редактируются на текущем времени,
жест отменяется одним Undo. Все элементы меню настроек постоянно увеличены в 1.5 раза:
текст, поля, кнопки и отступы. Все разделы изначально закрыты; открытие одного закрывает
остальные, повторное нажатие закрывает текущий. Редактирование не меняет масштаб панели.
Hidden, Solo и Locked доступны в инспекторе и на таймлайне.

Перенос клипа сдвигает все его ключи, фазу и дочерние эффекты вместе. Ручки обрезки начала/конца
меняют только интервал; обрезка не начинает эмиссию заново. Полосатый участок показывает хвост частиц.
`AFTER CLIP`: Cut обрывает слой, Drain оставляет родившиеся частицы до конца жизни, Fade гасит хвост
за 0.5 s. Для циклического дыма есть Prewarm. Continuous интегрирует частоту эмиссии; Burst создаёт
ровно заданное число частиц. Лимит 1–1200 (по умолчанию 600) пропускает новые рождения, сохраняя живые;
инспектор показывает число живых и пропущенных частиц. Максимальная жизнь — 10 s.

В Composition частицы сохраняют положение рождения, оставляя след при движении эмиттера;
в Local следуют за ним. Направление, угол/величина гравитации, ветер, дрейф, мерцание, растяжение,
шлейф, размер и RGB анимируются ключами. Size/Alpha/Color over life задают кривые возраста 0…1.
Формы источника: point, line, circle, rectangle и альфа-контур загруженного изображения. Без источника
альфа-контура эмиссия не создаётся. `Import particle PNG` добавляет собственную текстуру;
Atlas columns/rows и Sprite frames/s позволяют воспроизводить кадры атласа. PNG сохраняется в
локальном черновике; для переноса экспортированного JSON его нужно положить в asset registry.
Смешивание normal/add/screen/multiply задаётся для генератора.

Seek, пауза и loop воспроизводятся из progress и seed без накопленного frame delta. Планы рождения
и трансформации кешируются, спрайты используются повторно; неподвижный кадр не перестраивает частицы.
Анимированная частота интегрируется с шагом 1/120 s, постоянная — аналитически. При импорте v8
сохраняются прежние Local и Cut. Радиусы фильтров задаются в authored pixels и учитывают масштаб
композиции или локального ресурса. Aura остаётся самостоятельным свечением, не освещает terrain.

При замене PNG-стадий процедурные ресурсы сохраняются; фильтры удалённых PNG удаляются.
JSON и IndexedDB сохраняют параметры, зависимости и все ключи; процедурные assetId не загружаются
как изображения. Старые JSON без kind остаются изображениями.

`vfx` остаётся резервным extension-point массивом: новые эффекты хранятся в типизированных `stages`.
Sandbox не добавляет здание в
authoritative `GameState`: тестовый экземпляр остаётся presentation-only объектом renderer.

## Управление

Все изменяемые параметры правой панели автоматически сохраняются в `settings.json` в корне
проекта (с небольшой задержкой после изменения). При следующем запуске `npm run dev` или
`npm run preview` приложение загружает этот файл до создания симуляции. Повреждённые, устаревшие
или отсутствующие поля заменяются безопасными значениями по умолчанию; кнопка «Сбросить настройки»
также обновляет файл. В сохранение входят параметры симуляции и оружия, визуализация, шейдеры,
сглаживание и текстура рельефа, а также масштаб камеры.
Записи выполняются по очереди. Если сервер не сохранил настройки, под игровой сценой появляется
сообщение; следующее изменение повторит попытку. Несовместимый с размещением установок размер
мира в сохранённом файле заменяется стандартной игровой конфигурацией при запуске.

угол: Basic Cannon — 42°, Mortar — 70°, Heavy Penetrator — 8°; затем можно свободно прицеливаться.
Повторный выбор уже активного оружия сохраняет угол. Сброс сцены очищает очередь,
снаряды, кратеры, cooldown, счётчики, control groups и клиентские маркеры;
возвращает стартовый состав батарей. Настройки и пауза сохраняются.

## Камера и размер карты

Новые карты имеют размер **360 × 64 м** — три ширины базовой камеры **120 × 64 м**.
Масштаб камеры изменяется от **1× до 3×**; при 3× виден участок 40 × 21.33 м.
Генерация карты не зависит от размеров окна и текущего зума. Размеры базового кадра
и число его ширин в карте заданы в `src/game/config/worldLayout.ts`.

При одинаковом зуме игроки видят одинаковый участок мира независимо от разрешения,
плотности пикселей и соотношения сторон экрана. Игровой кадр вписывается с полями;
объекты и эффекты обрезаются по его границам. Поля не принимают игровые команды,
а рамка выделения не захватывает скрытые за кадром установки.

Камера перемещается стрелками, средней кнопкой мыши или Alt + ЛКМ и ограничена
краями карты. Скорость стрелок зависит от игрового времени кадра и масштаба,
а не от разрешения или частоты повторения клавиш. Камера работает и на паузе.
Колесо приближает к указателю; ползунок в разделе «Камера» — к центру кадра.
При сбросе сцены или создании нового рельефа камера возвращается к своей батарее,
сохраняя зум. «Сбросить настройки» возвращает масштаб 1×.

В правом нижнем углу сцены находится миникарта всего рельефа с маркерами установок:
свои — зелёные, противники — оранжевые. Прямоугольник показывает текущую область
обзора и меняет размер при зуме. Клик вне прямоугольника переносит камеру к указанной
точке; прямоугольник можно перетаскивать ЛКМ, сохраняя место захвата. Миникарта
обновляется при разрушении и смене рельефа, работает на паузе и не выдаёт боевых
приказов при навигации.

Положение и зум хранятся в клиентском `CameraController`, вне simulation state
и снимков. Освещение, марево и ударные волны привязаны к координатам мира;
полноэкранная постобработка ограничена видимым кадром.

## RTS-управление — Step 7

В каждой батарее по умолчанию: Cannon, Mortar, Mortar, Heavy Penetrator.
Противник не имеет AI. Установки не двигаются по горизонтали; разрушение опоры
корректирует высоту, а полная потеря опоры блокирует огонь.

Выделение, hover, рамка, группы 1…9 и режим выбора точки находятся в клиентском
`RtsController`, отдельно от simulation. Смерть очищает выделение и группы.
В simulation попадают команды с ID и владельцем: `attackGround`, `attackTarget`,
`stop`, `setWeapon`. Simulation сама проверяет владение и доступность оружия.

Один приказ — один выстрел. Без Shift очередь заменяется, с Shift дополняется
до 24 приказов. Stop очищает её, Shift+Stop пропускает активный приказ.
Очередь исполняется по возрастанию ID, не более одного приказа на установку за тик.
Во время перезарядки приказ ждёт. При недостижимой цели показывается
`NO BALLISTIC SOLUTION`, затем на следующем тике рассматривается следующий приказ.

Автоматический расчёт перебирает углы и уточняет лучшие кандидаты, используя реальные
`createProjectile` и `advanceProjectile`. Учитываются ветер, гравитация, сопротивление,
геометрия ствола и swept-столкновения. Поиск прекращает полёт кандидата на первом контакте,
не рассчитывает специальные маршруты с рикошетом или пробитием и не изменяет мир.
Угол ограничен диапазоном 5–85° к горизонту в обе стороны. Для точки допуск по умолчанию 1 m;
для Attack Target требуется прямой контакт с выбранным хитбоксом.

При одиночном выделении остаются ручной прицел, полный прежний прогноз и Space.
Ручной выстрел отменяет огневую очередь, сохраняя cooldown. Прогноз скрыт при
групповом выделении. Панель показывает HP, тип, оружие/Mixed, очередь и результат
расчёта; линии на карте соединяют установку с активной и последующими целями.
Бирюзовый центр башни обозначает Mortar, розовый — Penetrator, зелёный — Cannon.

В этом шаге тесты, typecheck, lint, build, браузерные проверки и замеры производительности
**не запускались по указанию пользователя**. Добавлены сценарии для последующего запуска.
Полный список изменений и ограничения: [отчёт Step 7](STEP7_REPORT.md).

В инспекторе отображаются профиль пробития и материал под курсором. В телеметрии
попадания — материал, SUCCESS / STOPPED / ВЫКЛЮЧЕНО, глубина, потерянная и оставшаяся
энергия, скорость выхода. «Путь пробития» записывает следующий контакт: оранжевая
точка обозначает вход, голубые — шаги расчёта, зелёная — выход, розовая — остановку.
Параметры penetration-профиля заданы в definitions и показываются только для чтения;
массу, начальную скорость, размер снаряда и кратер можно менять в прежних числовых полях.

Секция «Рикошет» позволяет включить механику и менять угол, минимальную скорость,
долю сохранённой энергии и число отражений. Изменения относятся к следующему выстрелу.
В телеметрии показаны STOP / PENETRATE / RICOCHET, угол, нормаль, оставшаяся/потерянная
энергия, скорость после отражения и счётчик. Toggle «Нормали поверхности» рисует голубую
стрелку от последнего контакта. Голубая точка на прогнозе отмечает один рикошет.
Поверхность исходной карты преимущественно Soil; Rock открывается после разрушения грунта.

## Взрывы — Step 6

Mortar детонирует при первом контакте с юнитом или рельефом. Профиль задаётся
через `ImpactDefinition.explosion`; проверки weapon ID в игровой логике нет.
Basic Cannon и Heavy Penetrator по умолчанию сохраняют кинетический урон,
кратеры, рикошет и пробитие. В инспекторе взрывы можно включить для любого оружия.

- Радиус поражения — **6 m**, зона полного урона — **1.5 m**.
- Урон — **60 HP** внутри этой зоны, далее линейно уменьшается до **5 HP** перед границей.
  На внешней границе и за ней — 0. Расстояние измеряется до края кругового хитбокса с учётом offset.
- Любая solid-ячейка между взрывом и центром хитбокса уменьшает урон до **25%**.
  Исходная ячейка взрыва пропускается. Soil и Rock одинаково закрывают путь.
- Кратер взрыва — **2.8 m**, независимо от AoE и кинетической энергии.
  Дополнительный кинетический кратер при взрыве не создаётся.
- Прямой урон применяется первым, затем AoE, затем разрушение рельефа.
  Укрытие оценивается по рельефу **до этого кратера**. Уже мёртвые цели пропускаются.
- Взрыв может повредить собственное орудие и союзные цели. Отбрасывания нет;
  обычная система размещения юнитов на поверхности продолжает учитывать кратеры.

Секция «Взрыв» редактирует настройки выбранного оружия. Изменения действуют на следующие
попадания, включая снаряды в полёте. Секция «Последний взрыв» показывает число целей,
ослабление, урон по каждой цели и фактическую максимальную потерю HP.
Отладочные переключатели показывают радиусы и линии к позициям целей в момент взрыва.
`ExplosionEvent` и `explosionResolved` живут один тик; runtime сохраняет только последнее
событие для отображения, отдельно от GameState и snapshots.

Подробности, список файлов и ограничения: [отчёт Step 6](STEP6_REPORT.md).

## Карточки урона

Каждое попадание по юниту создаёт карточку с рассчитанным уроном в точке контакта,
в том числе при нулевом уроне и уничтожении цели. Направление совпадает с направлением
снаряда при попадании. Общий источник карточек — `EntityDamageEvent`.
AoE создаёт отдельную карточку над каждой поражённой целью; при direct + AoE
получаются две карточки. Нулевой AoE не создаёт damage event. Взрывные карточки
поднимаются вверх без придуманной кинетической энергии. В правой панели, в разделе «Таблички урона», доступны:

- Начальная скорость: множитель скорости снаряда от ×0 до ×5; ×1 по умолчанию, ×0 оставляет карточку на месте.
- Начальный размер: множитель базового размера от ×0.25 до ×3; ×1 по умолчанию.
- Дистанция вылета: базовый путь карточки от 0 до 20 m; мощность удара увеличивает его до ×3.
- Время анимации: множитель от ×0.25 до ×3 для длительности вылета; ×1 по умолчанию.
- Скорость подъёма: постоянное движение карточки вверх от 0 до 5 m/s на всём протяжении анимации;
  по умолчанию 0.6 m/s.
- Кривая скорости: график кубической Безье с двумя перетаскиваемыми контрольными точками.
  По горизонтали показано время, по вертикали — множитель скорости; выше кривая означает,
  что карточка дольше сохраняет скорость. Доступны пресеты «Плавно», «Импульс» и «Инерция»;
  после фокуса точки можно также двигать стрелками, удерживая Shift для шага 0.05.

Настройки применяются при следующем попадании, сохраняются при сбросе сцены и возвращаются
к исходным значениям кнопкой «Сбросить настройки». Уже созданные карточки сохраняют свои параметры.
Скорость задаётся кубической кривой Безье с фиксированными точками `(0, 1)` и `(1, 0)`.
Длительность полёта пересчитывается по средней скорости кривой, а затем умножается на
настройку времени. При значении ×1 сохраняется заданная дистанция и остановка без обратного
движения; другие значения изменяют темп и фактический путь при той же начальной скорости.

Кинетическая энергия от 0 до 10 000 J увеличивает выбранный путь до ×3 и масштаб с ×1 до ×2 относительно выбранного размера;
выше этого порога множители ограничены. Для очень медленных попаданий полёт ограничен
пятью секундами с сокращением пути. После остановки карточка остаётся на 0.4 s и исчезает
за 0.3 s. Постоянные параметры пути и исчезновения находятся в `src/game/effects/DamagePopup.ts`;
параметры панели — в `GameConfig.damagePopup`.

Эффекты учитывают все попадания между кадрами, приостанавливаются вместе с симуляцией
и очищаются при сбросе сцены. Они отображаются независимо от отладочных переключателей
и хранятся в runtime отдельно от simulation state и snapshots.

```text
    rendering/           @pixi/react lifecycle и императивный Pixi-адаптер
    input/               DOM-события → команды
  ui/
    HUD/                 Телеметрия с частотой 10 Hz
    TechnicalPanel/      Числовые параметры, debug toggles, pause/step/reset
    useTelemetry.ts      Компактные данные только для HUD
  main.tsx               Создание runtime и React root
```

**React UI → команды → чистая TypeScript-симуляция → Pixi renderer.** Runtime
создаётся вне React-компонентов и владеет миром, конфигом, очередью и часами.
React не хранит координаты снарядов и не обновляет игровое дерево каждый кадр.
Pixi ticker передаёт длительность кадра в runtime, после чего renderer читает состояние.

- Единицы мира — метры, секунды, килограммы; **+x вправо, +y вниз**. Угол орудия
  положителен вверх от горизонтали: `vx = cos(angle) × speed`, `vy = -sin(angle) × speed`.
  `fitWorld`/`screenToWorld` изолируют масштабирование и поля по краям при resize.
- Симуляция использует accumulator и фиксированный шаг `1 / tickRate`.
  Один кадр ограничен 250 ms. `previousPosition`, `position` и clock alpha обеспечивают
  интерполяцию при отрисовке. Пауза не накапливает пропущенное время.
- Физика — semi-implicit Euler; ветер — ускорение по X, сопротивление — линейное
  затухание скорости `exp(-airDrag × dragCoefficient × dt)`. `gravityScale`,
  `windInfluence`, `dragCoefficient` — множители снаряда; у всех трёх типов равны 1.
  При нулевом сопротивлении действует
  обычная баллистика с численной погрешностью интегратора.
- Снаряд копирует ID оружия, снаряда и impact, массу, радиус, начальную скорость,
  максимальное время жизни, профили пробития/рикошета и множители гравитации, ветра, сопротивления
  при выстреле. Изменения этих полей влияют на **следующие** снаряды. Изменение
  гравитации, ветра и сопротивления действует на существующие снаряды со следующего тика.
- Definitions — неизменяемые данные и единственный источник defaults.
  `GameConfig` хранит мир и необязательные `weaponOverrides[weaponId]`:
  секции `weapon`, `projectile`, `impact`, `ricochet`, `explosion`. Панель редактирует overrides выбранного оружия;
  переключение их сохраняет, «Сбросить настройки» удаляет все overrides.
- Энергия вычисляется общей `calculateKineticEnergy` как `E = 0.5 × mass × (vx² + vy²)`;
  она не редактируется и не вычисляется отдельной формулой в UI.
  Радиус кратера: `clamp(base + sqrt(E) × scale, base, max)`.
  Удар использует текущую скорость снаряда. Настройки кратера применяются в момент удара
  для оружия, запустившего снаряд, независимо от текущего выбора в панели.
- Рельеф 360 × 64 m по умолчанию хранится в сетке 3600 × 640 ячеек размером 0.1 m.
  В правой панели можно выбрать ячейку 0.025, 0.05, 0.1, 0.2 или 0.4 m.
  При 0.025 m карта содержит 14 400 × 2 560 ячеек. Смена размера пересоздаёт рельеф
  с текущим seed и сбрасывает сцену; «Сбросить настройки» возвращает 0.1 m.
  Ячейки содержат `Air = 0`, `Soil = 1`, `Rock = 2`; сопротивления хранятся в отдельном registry.
  Отдельная авторитетная occupancy-маска разделена на настраиваемые chunks по 256 × 256
  ячеек и упакована в `Uint32Array` по 32 горизонтальных пикселя на слово.
  Rock начинается на глубине `6 ± 1.5 m` от поверхности; материал имеет отдельный seeded stream.
  Companion `*_density` выбранной Rock-текстуры (или `*_alpha`, если density отсутствует)
  преобразуется на browser boundary в сериализуемый
  профиль глубины и изменяет авторитетные Soil/Rock-ячейки. Смена текстуры или ориентации
  пересоздаёт terrain с текущим seed; collision, пробитие и разрушение используют новую границу.
  Companion `*_density` задаёт неоднородную прочность Rock: чёрный — 0.5×,
  белый — 2× исходного сопротивления, промежуточная яркость плавно меняет коэффициент.
  Кратеры и каналы удаляют ячейки по расстоянию с учётом локальной прочности
  (`локальный радиус = исходный радиус / sqrt(коэффициента)`); пробитие расходует энергию
  с тем же коэффициентом. Soil сохраняет прежнее поведение.
  Минимальный канал под габариты прошедшего снаряда сохраняется даже в плотном камне.
  Без density-маски, включая ошибку её загрузки, расчёт разрушения и пробития остаётся прежним.
  `terrain.rockDepthMeters = null` возвращает all-Soil генерацию для baseline.
  Генератор воспроизводим по seed: поверхность задаётся синусоидами и плавным шумом с опорными
  точками через 12 m и квинтической интерполяцией. Шум не зависит от плотности сетки.
  Столбцы выбирают высоту в своём центре; клетка заполняется, когда её центр лежит ниже поверхности.
  Вертикальная ошибка границы не превышает половины клетки вдали от ограничений карты.
  Новая генерация меняет карту для прежних seed; нажмите «Сбросить сцену», чтобы её увидеть.
  Бинарные ступеньки размером в клетку сохраняются, но мелкий шум на каждом столбце устранён.
  Дробные высоты сохраняются в `initialSurfaceMeters` и передаются renderer: нетронутый внешний
  контур рисуется по ним, а удалённые клетки вычитаются из исходной формы. Добавленные клетки
  объединяются с ней. Карты без исходного профиля используют восстановление из бинарной маски.
  Орудие устанавливается по запросу поверхности
  на 17% ширины карты. Свойства генерации находятся в конфиге.
- Swept collision проверяет сегмент с шагом не больше половины ячейки, учитывает
  радиус снаряда и уточняет первый контакт бинарным поиском. Collision не решает судьбу снаряда.
  Collision также возвращает нормаль и точку касания поверхности, отличную от центра снаряда.
  `resolveImpact` возвращает `stop` / `penetrate` / `ricochet` и semantic damage operations:
  `{ type: 'circle', center, radiusMeters }` или `{ type: 'capsule', from, to, radiusMeters }`.
  `TerrainDamageEvent` содержит `operation`; удаляются ячейки по их центрам.
- После повреждения тонкие горизонтальные следы грунта толщиной до трёх клеток ожидают
  50 мс симуляционного времени. Близкие следы объединяются, затем их клетки падают
  в течение 240 мс и образуют на опоре насыпь по количеству осевшего материала.
  Во время падения они отображаются отдельно от сетки; в конце материал возвращается
  в `TerrainGrid`. Широкий рельеф не участвует.
- Renderer читает immutable dirty-журнал `TerrainGrid`, объединяет изменения по chunks и
  передаёт Web Worker material-область с halo. Worker строит компактное RGBA-поле расстояний,
  материала и оттенка; один Pixi mesh на chunk реконструирует край и накладывает исходную текстуру
  Rock на GPU в абсолютных мировых координатах. PNG больше не уменьшается и не запекается в
  растровую маску рельефа; линейная фильтрация, mipmaps и anisotropy сохраняют детали на разных
  масштабах. При ошибке загрузки остаётся базовый цвет материала. Collision всегда читает CPU
  bitmask; GPU → CPU readback отсутствует. В правой панели
  отдельный блок «Текстуры рельефа» показывает активный Soil-ассет `soil_1` и выбирает
  Rock-текстуру. Поддерживаются обычные albedo-файлы и комбинированный формат 2:1 с цветом
  в левой половине и normal map в правой. Перед загрузкой в GPU половины разделяются, чтобы
  фильтрация и mipmaps не затягивали край normal map в цветовую текстуру. Все изображения
  Обычные `stone*` и комбинированные `*_mixed` из `public/Textures/Environment` автоматически
  добавляются в список при запуске
  Vite или сборке. Companion `*_density` и `*_alpha` автоматически связываются
  с соответствующей обычной или mixed-текстурой. Верхнюю границу Rock и в simulation-grid,
  и в renderer формирует `*_density`, если она есть; иначе используется `*_alpha`.
  Companion `*_density` не попадает
  в список обычных текстур. Его яркость декодируется в сериализуемую сетку до 512×512
  отсчётов; масштаб, зеркалирование и случайный поворот совпадают с world-space UV камня.
  Density применяется при пересоздании сцены после смены текстуры/ориентации; preview
  копирует её вместе с terrain, а snapshot содержит отдельную числовую копию.
  Ориентация плиток переключается между зеркальной, последовательной,
  зеркальной по одной оси и детерминированно случайной. Экранное сглаживание края использует
  билинейное восстановление сглаженного поля знакового расстояния (SDF), экранные производные
  и 1×1, 2×2, 4×4, 8×8 или 16×16 выборок на пиксель; последние уровни
  дороже для GPU. Поле хранит расстояния и снаружи рельефа в непрозрачной data texture,
  поэтому внешний край сглаживается так же, как внутренние контуры. Выключение показывает точную
  бинарную границу. Rock выбирается отдельно с градиентами непрерывных мировых UV для mipmaps.
  Форма края восстанавливается из расстояний, а число выборок определяет точность экранного AA.
  Узкие стенки и каналы сохраняют исходное поле расстояний локально. Это адаптация подхода
  [Rocket Bot Royale](https://briansemrau.github.io/sdf-rendering-optimization/) к CPU-сетке:
  исходная геометрия остаётся дискретной, поэтому субклеточная форма приближённая.
  Debug-переключатели показывают collision mask,
  границы chunks и последний dirty rectangle (`F3`, `F4`, `F5`).

- В секции «Шейдеры и эффекты → Динамический свет камня» курсор управляет одним
  точечным источником. Для выбранной каменной текстуры однократно строится Height Map
  (яркость и локальный контраст). Если рядом с albedo есть PNG с постфиксом `_normal`,
  используется он; иначе Normal Map генерируется из высот. Карты кешируются при
  переключении текстур.
  Шейдер объединяет нормали материала с градиентом текущего контура рельефа, поэтому новые
  края воронок реагируют на свет. Доступны интенсивность, радиус, выраженность нормалей,
  фоновый свет, цвет источника, режим наложения (умножение, сложение, экран) и просмотр
  albedo, высоты, нормалей или итогового изображения.
  Освещение диффузное, без падающих теней и PBR.
  Renderer-only registry `terrainMaterialVisuals` отделяет оформление Soil/Rock от их
  игровых свойств и служит точкой расширения для детализированных вариантов материалов.
  Прогноз кешируется по конфигу, оружию, углу и версии рельефа. Он вызывает ту же функцию
  `advanceProjectile` и `resolveImpact`, показывает максимум один рикошет и заканчивается
  перед пробитием или следующим контактом. При рикошете создаёт одну временную копию
  terrain и применяет тот же скол; исходный grid и его версия сохраняются.
- `state.events` содержит события только текущего тика: `projectileSpawned`,
  `projectileImpact`, `entityImpact`, `entityDamage`, `impactResolved`, `explosion`,
  `explosionResolved`, `terrainDamage`; очередь очищается в начале следующего тика.
  Для каждого снаряда последствия применяются сразу, поэтому следующие снаряды
  того же тика видят уже изменённый грунт, как в baseline.
  `lastImpact` сохраняет результат последнего попадания для HUD: исходное оружие,
  тип снаряда, скорость, энергию, координаты, радиус кратера, удалённые ячейки и summary пробития.
  Полные traversal segments живут только в transient resolution; включённый debug сохраняет
  последний путь в runtime отдельно от simulation state.
  `createGameSnapshot` создаёт отдельную JSON-сериализуемую копию по запросу.

Simulation не импортирует React, Pixi, DOM, часы системы или нефиксированную случайность.
Это закреплено ESLint и отдельным `tsconfig.simulation.json` с `lib: ["ES2022"]`.
Ядро можно вынести в пакет и использовать на Node.js-сервере, в replay runner или AI.
Сетевой протокол, replay-система и AI в MVP не реализованы.

```text
Input → FireCommand → Cannon.weaponId → WeaponDefinition + ProjectileDefinition
      → createProjectile → ProjectileState → общая физика

TerrainCollision → ImpactEvent → ImpactContext → resolveRicochet
                 → если рикошет не разрешён: createActivePenetration / stop
                 → ImpactResolution(stop / penetrate / ricochet)
                 → TerrainDamageEvent.operation → removeCircle / removeCapsule
                 → остановка, пробитие или отражённая скорость → следующий тик
```

Collision не вычисляет кратер. Resolver возвращает данные без мутации terrain.
`TerrainDamageEvent` можно сериализовать и применить к другой копии terrain.

Пробитие проходит по направлению скорости с шагом `cellSize / 2`; при входе создаётся
bounded material trace из исходного terrain до применения канала. Цена шага:
`ΔE = penetrationResistance × distance / penetrationPower`.
Soil имеет сопротивление 1500 J/m, Rock — 12000 J/m. Это игровые коэффициенты.
Успех требует, чтобы весь круг снаряда вышел в Air с энергией выше `minimumExitEnergyJ`.
Скорость выхода: `normalize(impactVelocity) × sqrt(2 × remainingEnergyJ / massKg)`.
При нехватке энергии последний шаг сокращается; создаётся частичный канал.
Лимиты: заданная максимальная глубина и максимум 4096 samples.

Канал растеризуется как непрерывная capsule. Чтобы между центрами ячеек не остались
зацепы для снаряда, его радиус не меньше `projectileRadius + cellSize × (√½ + 0.001)`.
Для Heavy Penetrator default это около 0.302 m при заданном profile radius 0.18 m.
Инспектор показывает фактический радиус. Кратер по прежней формуле независим от канала;
blast resistance сохранён в definitions как справочное значение и пока не влияет на кратеры.

Нормаль — обратный градиент occupancy в ядре 5×5: для геометрии Soil и Rock равны 1,
Air равен 0. Нормализация защищена от нулевых/нечисловых векторов; fallback направлен
против движения, а при неопределённом движении — вверх. Угол вычисляется единым helper:
`acos(clamp(-dot(incomingDirection, normal), -1, 1))`.
**0° — лобовое, 90° — касательное попадание.** Уходящий контакт (>90°) не отражается.

Рикошет детерминирован. Soil/Air имеют `ricochetFactor = 0`, Rock — `1`.
Формулы: `reflected = v - 2 * dot(v, n) * n`, `remainingE = E * retention`,
`speedAfter = sqrt(2 * remainingE / mass)`. Минимальная скорость проверяется до и после
рикошета; при слишком малой остаточной скорости снаряд останавливается.
Скол имеет радиус 0.16–0.30 m (Heavy Penetrator — до 0.25 m) и рассчитывается по потерянной
энергии. Перед продолжением полёта выполняется ограниченный поиск свободного положения
вдоль нормали с шагом `max(cellSize * 0.1, radius * 0.1)`; position и previousPosition
получают отдельные копии. Подробнее: [отчёт Step 4](STEP4_REPORT.md).

## Шейдеры и постобработка

В боковой панели появился раздел **«Шейдеры и эффекты»**. Все разделы и вложенные
подменю панели изначально свёрнуты. У каждого эффекта есть переключатель и настройки,
которые применяются сразу, в том числе на паузе. Общий выключатель сохраняет выбранные
значения; кнопка сброса возвращает настройки эффектов по умолчанию.

Доступны 12 фильтров PixiJS / `pixi-filters` 6:

- Рельеф: Bevel и освещение по карте света, включая локальный свет от взрывов.
  Карта света учитывает смещение и масштаб камеры.
- Сцена: ColorMatrix и Noise; Blur применяется к фону.
- Установки: DropShadow и Outline для выбранных корпусов.
- Боевые эффекты: Glow, AdvancedBloom, Shockwave, локальный Displacement и
  индивидуальный MotionBlur по скорости каждого снаряда.

По умолчанию включены восемь умеренных эффектов. Зерно, размытие фона и движения,
а также марево включаются отдельно. Настройки действуют до перезагрузки страницы.
Подписи, индикаторы здоровья и отладочные линии остаются в отдельном слое.

Настройки находятся в `src/game/rendering/ShaderSettings.ts`, управление фильтрами —
в `ScenePostProcessing.ts`, карты света и марева — в `TerrainEffectMaps.ts`.
Карты имеют размер 240 × 128; статический свет пересчитывается при изменении рельефа,
анимированные карты обновляются до 30 раз в секунду. Одновременно отображаются до
четырёх волн искажения. Runtime сохраняет до 32 недавних взрывов в течение пяти секунд,
вне состояния симуляции и снимков. Пауза останавливает эффекты, сброс очищает их.

## Ограничения MVP

- Одно управляемое орудие и одна цель. Групповое управление не реализовано.
- Взрыв проверяет один луч до центра хитбокса. Толщина/материал укрытия и частичное
  перекрытие не моделируются; любой solid за пределами исходной ячейки ослабляет урон.
- Грунт после разрушения не осыпается. Точность контура ограничена выбранным размером ячейки.
- Края карты слева/справа и низ завершают жизнь снаряда; верх открыт, поэтому
  снаряд может вернуться сверху. Очень быстрый выстрел может уйти за карту без попадания.
- Прогноз учитывает текущий рельеф; другой летящий снаряд может изменить его до попадания.
- Кратеры ограничены maximum radius; после достижения лимита рост энергии не увеличивает их.
- Интегратор приближённый, swept sampling также приближённый в касательных случаях.
  Межмашинный lockstep determinism не гарантируется.
- Полная texture обновляется при разрушении; chunking пока не нужен.
- Требуется браузер с WebGL. Основной сценарий — desktop, панель адаптируется под узкий экран.
- Нет backend, сети, AI, экономики, сохраняемой игры или стороннего physics engine.
- При контакте создаётся активное состояние пробития. На каждом fixed tick снаряд проходит
  не больше `speed × dt` внутри материала; его скорость пересчитывается из оставшейся энергии.
  После выхода обычный баллистический полёт возобновляется со следующего тика.
- Цена материала приблизительна до половины ячейки на границах. В смешанном контакте
  используется материал центра, а если центр в Air — первая касающаяся ячейка.
- Остаточная энергия при STOPPED — неизрасходованный бюджет traversal; остановленный
  снаряд удаляется, его скорость нулевая. Прогноз заканчивается до пробития.
- Нормаль сглажена сеточным ядром и приблизительна на углах, тонких выступах и краях карты.
  Рикошет ограничен профилем снаряда (UI: до 8); прогноз показывает только первый.
  Остаток fixed tick после контакта не доинтегрируется; полёт продолжается на следующем тике.
- На очень крупной сетке скол может не затронуть центр ни одной ячейки. Это ограничение
  растеризации circle damage; параметры скола не расширяются до полного кратера.
