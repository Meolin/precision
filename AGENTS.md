# Руководство для агентов

## Назначение проекта

Ballistics Lab — локальный MVP 2D RTS-полигона. Игрок управляет четырьмя стационарными установками: выбирает их, отдаёт приказы огня и наблюдает за баллистикой, разрушением рельефа, уроном и взрывами.

Главный принцип: **React UI → сериализуемые команды → чистая TypeScript-симуляция → Pixi renderer**. Не переносите игровую логику в React и не позволяйте renderer или input напрямую менять `GameState`.

## Среда и команды

- Node.js: `>=22.12.0`; пакетный менеджер: npm.
- Запуск: `npm run dev`.
- Полная проверка перед сдачей изменения: `npm run typecheck`, `npm run lint`, `npm run test`, `npm run build`, `npm run format:check`.
- Автоформатирование: `npm run format`.

Не утверждайте, что проверка прошла, если она не запускалась. В исторических отчётах Step 4, 6 и 7 часть тестов намеренно не запускалась; это не заменяет свежую проверку.

## Карта модулей

- `src/app`, `src/ui` — React layout, панель и компактная телеметрия.
- `src/game/core` — runtime, состояние, fixed timestep, tick и snapshot.
- `src/game/commands`, `src/game/orders` — намерения игрока и их выполнение.
- `src/game/entities`, `src/game/weapons`, `src/game/ballistics` — установки, определения и полёт снарядов.
- `src/game/collision`, `src/game/impacts`, `src/game/combat`, `src/game/explosions` — контакты и разрешение последствий.
- `src/game/terrain` — сетка, материалы, коллизии и разрушение.
- `src/game/rendering`, `src/game/client`, `src/game/input` — адаптер Pixi, камера, RTS-ввод и локальное выделение.

Подробности: [ARCHITECTURE.md](ARCHITECTURE.md). Актуальный продуктовый срез: [CURRENT_STATE.md](CURRENT_STATE.md). Обоснования решений: [DECISIONS.md](DECISIONS.md).

## Непереговорные границы

- Simulation не импортирует React, Pixi, DOM, системные часы или нефиксированную случайность. Это проверяется отдельным `tsconfig.simulation.json` и ESLint.
- Изменение мира выполняется только в `stepSimulation` и вызываемых им системах. UI и renderer читают состояние, а input создаёт команды.
- Definitions — неизменяемый источник defaults. Изменяемые настройки пользователя хранятся в `GameConfig.weaponOverrides` и применяются с документированным моментом времени.
- Collision возвращает геометрические факты, а не уничтожает снаряд и не мутирует terrain. Impact/explosion resolvers возвращают данные; события применяют последствия.
- Команды и приказы содержат ID, а не ссылки на объекты. Валидация ownership, жизни сущности и совместимости оружия остаётся на simulation boundary.
- Все координаты — метры, время — секунды, масса — килограммы. Ось `+x` направлена вправо, `+y` вниз; положительный угол орудия направлен вверх.

## Как вносить изменения

1. Найдите владельца поведения в существующем модуле; избегайте преждевременной «универсальной» абстракции и массового переноса файлов.
2. Сохраняйте детерминизм: передавайте все входы явно, не используйте `Math.random`, Date или frame delta в simulation.
3. Для новой логики добавляйте изолированные unit-тесты рядом с модулем и интеграционный/regression-тест, когда меняется pipeline.
4. При изменении пользовательского поведения обновите `README.md`, а при изменении границ/решений — этот набор документов.
5. Не удаляйте существующие тесты, snapshot или исторические отчёты ради прохождения проверки.

## Технические соглашения

- Fixed timestep: accumulator, шаг `1 / tickRate`; frame delta ограничен 250 ms. Пауза не должна накапливать время.
- Состояние `state.events` — только события текущего тика; его очищают в начале следующего тика. Последствия снаряда применяются по порядку, поэтому поздние снаряды видят изменения ранних.
- `createGameSnapshot` должен оставаться отдельной JSON-сериализуемой копией.
- Траекторный preview вызывает те же ballistics/impact helpers, что и live-полёт, но не должен менять основной terrain или simulation state.
- Локальные UI-состояния (hover, selection, control groups) не кладите в `GameState`.

## Текущие ограничения MVP

Не добавляйте как побочный эффект сетевой протокол, replay, ECS, полноценный AI, мобильность установок, экономику, броню, fragmentation, delayed detonators или физическое осыпание грунта. Это отдельные последующие этапы.
